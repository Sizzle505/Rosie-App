## Release provenance and validation

The private Dropbox artwork handoff contains 72/72 exports. A protected Vercel QA-art deployment holds all 72 (62,929,395 original bytes), SHA-256 matched to `asset-manifest.json`. The disposable isolated builder re-verifies every SHA-256 before replacing any source art, converts necessary WebP/PNG/JPEG/SVG files with Sharp, preserves the hollow QR aperture, updates newly active Reviews and Calculations navigation images, and eliminates fallback to Rosie coins.

The build then AST-rewrites visible Rosie copy without renaming code identifiers, removes Captain/Card Vault/Haiku navigation and disallowed direct app pages, substitutes an offline account context so Reminders work locally, preserves the two legacy recipe dish image slugs, and disables all backend routes. It also produces Teddy-branded iPhone/PWA icons from the verified crest.

## Important limits

These tests validate release routing and image loading, not image artistic approval or a complete real-world functional test of every feature. Nine corrected images in the source manifest retain `awaiting final approval` metadata; the approved production decision was to release the user's requested batch, subject to later aesthetic refinements.

**Accounts, cloud notes, Secret Santa persistence/registration, and email remain intentionally disabled in TeddyVerse** until separately provisioned. QR scans have visual/load QA but no physical cross-device scan assertion. The original Vercel build's RosieVerse fallback remains only in its now protected rollback project and is not attached to the public short URL.

## Subsequent maintenance

Use `build-isolated.mjs`, `rebrand-isolated.mjs`, and `brand-pwa.mjs` in a disposable isolated checkout with the hash-verified asset source. Do not merge the pet-specific overlay into RosieVerse's production branch. If backends are introduced, provision a separate database/sender and independently verify any login, mail or persistent workflows before activation.
